# Встречи: залы, места и переносы

Зал и лимит мест хранятся у встречи независимо от проекта. `capacity` в DTO остаётся числом участников проекта. `participantCount` считает записи `meetUser`, включая запись ученика, чьи данные больше не доступны для отображения; это согласует заполненность карточки с серверным ограничением мест. Новые встречи требуют положительного целого `maxParticipants`; прежний `NULL` означает отсутствие ограничения. PUT без новых полей сохраняет их значения. Установленный лимит нельзя очистить или уменьшить ниже числа записей `meetUser`.

Формы и календарь показывают МСК и отправляют время с `+03:00`. Соединения приложения используют московский часовой пояс для MySQL `TIMESTAMP` и календарных SQL-функций. API возвращает время как ISO с часовым поясом.

Для управления центром запросы используют существующие `X-Role: place` и `X-Place-Id`. Сервер проверяет роль `admin` в `placePassport` и совпадение центра встречи. Учитель редактирует собственные встречи; изменение начала, длительности или зала возвращает заявку в `pending`. Администратор сохраняет статус, а подтверждение отдельно проверяет пересечения.

Сохранение расписания выполняется при `READ COMMITTED`: сначала блокируется строка преподавателя, затем строки старого и нового зала по возрастанию ID, затем строка встречи. После получения блокировок сервис проверяет часы работы и пересечения с `pending`/`published` и сохраняет изменения в той же транзакции. Проверка пересечений читает актуальные зафиксированные строки; незаданный зал не блокирует центр. Запись ученика и изменение лимита используют блокировку строки встречи; конфликт возвращает 409.

## Применение миграции

Перед подключением следовать [mysql-access.md](mysql-access.md). Команда без `--apply` только читает предварительный отчёт:

```powershell
npm.cmd run db:migrate:meet-scheduling
node .cache/demo/cli/scripts/migrate-meet-location-capacity.js --apply
node export-db-schema.mjs
```

Миграция [005-meet-location-capacity.sql](../migrations/005-meet-location-capacity.sql) добавляет nullable поля, индексы, внешний ключ и ограничение положительного лимита. CLI сохраняет список переносимых залов в игнорируемом `.cache/meet-migration/`, переносит только активные залы соответствующего центра и оставляет старые лимиты `NULL`. DDL фиксируется MySQL отдельно; заполнение залов и запись маркера `005-meet-location-capacity` в служебную таблицу `quantumMigration(name, appliedAt)` выполняются одной транзакцией. Маркер предотвращает повторное заполнение залов после изменений проекта или ручного снятия выбора. После разрыва связи сначала прочитать поля и маркер; запись не повторять вслепую.

**Состояние на 11 октября 2026, 19:31 UTC:** миграция применена к рабочей БД. После прежних ошибок подключения повторный запуск обычного Node со скомпилированным CLI и явным TCP-потоком успешно выполнил предварительное чтение, запись и проверку после `COMMIT`. Через отдельное соединение подтверждены nullable поля `locationId`/`maxParticipants`, внешний ключ `fk_meet_location`, ограничение `chk_meet_max_participants` и маркер `005-meet-location-capacity` (19:30:58 UTC). Всего 90 встреч; подходящих залов проекта для переноса не было, поэтому у существующих встреч оба поля остались `NULL`. Резервный список сохранён в `.cache/meet-migration/2026-10-11T19-30-45-390Z/backfill.json`. [database-schema.md](../database-schema.md) повторно выгружен командой `node export-db-schema.mjs` в 19:31:49 UTC. Имеющиеся пересечения автоматически не исправлялись.

## Проверки

```powershell
npm.cmd test
npm.cmd run check
npm.cmd run test:meet-scheduling:db
```

Последняя команда требует отдельную локальную MySQL-совместимую БД на `127.0.0.1:33079` (настройки `DEMO_TEST_DB_PORT`, `DEMO_TEST_DB_USER`, `DEMO_TEST_DB_PASSWORD`). Она не загружает `.env`, создаёт БД со случайным именем и удаляет только её. Проверяются настоящий CLI миграции и его повторное применение, конкуренция за последнее место, изменение лимита одновременно с записью, конфликтующие переносы, занятость учителя в другом центре, соседние интервалы, откат подтверждения, статусы и московское время.
