## Импорт расписания от 15 октября 2026 года

Постоянный исходник и результат — [wschool-schedule.json](../wschool-schedule.json). Он содержит фотографию-источник из Google Drive, все 12 направлений, назначения преподавателей, ссылки на их профили и созданные проекты, ID встреч, источники фотографий и причины пропусков. Исходный JSON для скачивания также обновляется в игнорируемой `.cache/drive-analysis/zhivoy-istochnik-schedule.json`.

```powershell
npm.cmd run db:import:wschool-schedule
npm.cmd run db:import:wschool-schedule -- --apply
```

Первая команда выполняет предварительную сверку без изменения БД. Для воспроизведения подключения с явным TCP-потоком допускается `--stream`. Используются настройки `.env`, МСК и общий advisory lock `quantum:demo-seed`. Автоматических повторов записи нет. Период сохраняется в JSON до записи; повторный запуск использует тот же период и реестр `quantum-wschool-schedule-v1`, а не создаёт новый месяц занятий.

Сначала проверяются фактические столбцы, InnoDB, отсутствие непроверенных триггеров, однозначность аккаунтов и проектов. Фотографии сопоставляются по подписям карточек https://wschool.ru/#teachers; видимая полная подпись имеет приоритет перед метаданными изображения, поскольку на сайте есть устаревшие подписи. Оригиналы загружаются в S3 с постоянным ключом `teachers/wschool-597/{passportId}-{hash}.{extension}`. Отсутствующая фотография не заменяется произвольным изображением.

Изменения БД выполняются транзакцией после резервной выгрузки в `.cache/drive-analysis/wschool-*/backup.json`. Выгрузка аккаунтов содержит только поля справочника; email и токены не копируются. При ошибке SQL изменения откатываются; подготовленные файлы S3 могут сохраниться и повторно используются по тому же ключу. После обрыва сначала выполнить предварительную сверку, без слепого повтора `--apply`.

## Первоначальная настройка

Перед запуском CLI из окружения агента прочитайте [порядок работы с MySQL](mysql-access.md). Он описывает подтверждённый запуск через обычный Node и проверку состояния после обрыва соединения.

Помещения центра №597: `npm run db:setup:wschool-rooms` показывает предварительный отчёт; `npm run db:setup:wschool-rooms -- --apply` добавляет отсутствующие активные помещения «мастерская», «актовый зал», «кабинет дополнительный» одной транзакцией. Повторный запуск сохраняет ID. Резервная копия: `.cache/demo/cleanup/wschool-rooms-*/`. Изолированная проверка: `npm run test:wschool-rooms:db` (тот же локальный тестовый сервер, описанный ниже).

`npm run db:setup:wschool` показывает предварительный отчёт. Для записи:

```sh
npm run db:setup:wschool -- --apply
```

CLI использует подключение из `.env`, проверяет фактическую схему, сохраняет затронутые строки в игнорируемую папку `.cache/demo/cleanup/wschool-*/` и выполняет изменения одной транзакцией. После записи читает результат. При потере соединения сначала запустите предварительный отчёт: автоматического повтора записи нет.

Данные реального центра зарегистрированы отдельно от вымышленных демонстрационных наборов: `quantum-wschool-real-v1`. Повторный запуск сохраняет ID и не обновляет существующие записи. Изменённые пользователем записи, неоднозначные совпадения и пересечения расписания требуют проверки оператора.

Администратор и мастер — существующий аккаунт №42 «Дмитрий А.» (Дмитрий Александрович Галкин). Десять остальных преподавателей имеют справочные профили `quantum-directory` без email, токена доступа и вымышленных фотографий. Авторизация таких профилей запрещена.

Центр работает с понедельника по пятницу, 08:00–18:00 МСК. Контакты сохраняются в описании, телефон — также в существующем поле `phone`. Координаты взяты из карты на официальном сайте https://wschool.ru/.

Изображение создано встроенным imagegen по фотографиям изделия и заранее загружено через `FileService.uploadBuffer` с постоянным ключом `idea-catalog/toy-001-generated-cover-v1.png`.
