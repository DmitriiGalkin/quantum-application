# Упрощение Quantum

Публичные пути API сохранены. Идеи каталога продолжают использовать единую сущность `Idea`, постоянные ID, исходные данные, пометки о предположениях и ссылки на фотографии в S3. Изменения платёжного протокола и схемы второго этапа описаны ниже.

## Backend

- `src/app.ts` собирает Express-приложение; `src/backend.ts` запускает сервер.
- Контроллер разбирает HTTP-запрос, сервис проверяет права и выполняет бизнес-операцию, репозиторий работает с таблицей. В типе `Controller<Response, Body, Query>` тело запроса идёт перед параметрами поиска.
- Ошибки передаются через `HttpError` в единый обработчик. Он отправляет один ответ и скрывает внутренние подробности ошибки сервера.
- Запись требует авторизации. Изменение проекта, встречи и сообщения дополнительно проверяет владельца; управление центром — администратора. Чтение публичных проектов и callback платёжного провайдера доступны без пользовательской сессии. Callback проверяется подписью провайдера.
- Списки идей, проектов и встреч загружают связанные записи пакетами; связь устанавливается по ID. `ParticipantsService` собирает участников и проверяет принадлежность ребёнка аккаунту.
- Обновления используют разрешённые поля. Создание центра с администратором и расписанием, удаление связанных записей и создание личного диалога выполняются в транзакциях. Создание диалога блокирует аккаунты в одинаковом порядке, чтобы параллельные запросы не создавали дубли.
- Повтор при разрыве подключения допустим только для `SELECT`. Запись автоматически не повторяется: сервер мог выполнить её до обрыва связи. Ошибка отката не подменяет исходную ошибку транзакции.

## Frontend и SSR

- Контекст авторизации и доступ к браузерному хранилищу вынесены из провайдера. Серверный снимок не зависит от `localStorage`; права выбранной роли проверяются по загруженному профилю.
- Смена аккаунта или роли отменяет запросы и сбрасывает кеш. Ключи списков различают ученика, преподавателя и центр; мутации инвалидируют связанные списки и панели.
- Создание проекта использует выбранный центр. Создание центра обновляет профиль перед переключением контекста.
- Карты используют общий жизненный цикл Leaflet; слои и React-корни всплывающих окон освобождаются при очистке.
- SSR определяет метаданные идеи и проекта по пути, независимо от query string.

## Проверка

`npm run check` запускает ESLint, TypeScript и сборки клиента, SSR и backend. `npm test` проверяет HTTP-маршруты, права доступа, пакетную загрузку, транзакции, повторы запросов, SSR-гидратацию и кеш.

Каталог можно проверить без записи командой `npm run db:import:ideas -- toy-catalog.json --verify-only`. Для этого требуется подключение к MySQL из `.env`.

## Второй этап

### Статистика центра

Демонстрационные значения заменены данными MySQL:

- Преподаватели — уникальные аккаунты с ролью `teacher` в `placePassport`; администраторы без этой роли не учитываются.
- Проекты — проекты центра без `deletedAt`.
- Ученики — уникальные активные дети, записанные в активные проекты или неудалённые, неотменённые встречи центра. Участие в нескольких проектах и встречах не увеличивает счётчик.
- Встречи — неудалённые, неотменённые встречи текущей календарной недели с понедельника до следующего понедельника. Границы рассчитываются в часовом поясе сессии MySQL.
- Заявки на бронирование — будущие неудалённые встречи со статусом `pending`, независимо от недели.

`incoming` возвращает `null`, денежная карточка скрыта. Доход центра не равен общей сумме оплат учеников. Кроме того, комментарий `payment.amount` описывает копейки, а существующий код записывает цену встречи и передаёт её в Robokassa как рубли. Единицы сумм и исторические платежи в этом этапе не пересчитываются.

### Загрузка страниц и SSR

Страницы импортируются через `React.lazy`, общий макет остаётся доступным при переходах. Локализация календаря подключается внутри поля даты, вместе со страницами встреч.

SSR использует [`prerenderToNodeStream`](https://react.dev/reference/react-dom/static/prerenderToNodeStream) и собирает полный HTML после загрузки отложенных страниц. Завершённые Suspense-блоки остаются непосредственно в HTML, включая большие страницы. На клиенте сохраняется `hydrateRoot`. Ошибка импорта завершает SSR ошибкой, вместо успешного ответа с индикатором загрузки.

Для измерений сборка сохраняет manifest. Команда `node scripts/measure-client.mjs` после сборки считает JavaScript приложения и главной страницы вместе со статическими зависимостями, без остальных страниц и Leaflet. Исходная сборка загружала 370,51 КБ JavaScript после gzip. После разделения главная страница загружает около 271,97 КБ: на 27% меньше. Это измерение размера передаваемых файлов, а не времени загрузки на устройстве.

### Платежи

Новые платежи встреч используют провайдера `robokassa`; миграция `002-robokassa-provider.sql` добавляет его к существующему ENUM. Команда `npm run db:migrate:payments` проверяет схему и допускает повторный запуск. Старые платежи с меткой `yookassa` не переименовываются.

ResultURL возвращает текст `OK{InvId}`, как требует [Robokassa](https://docs.robokassa.ru/ru/notifications-and-redirects), без JSON-кавычек. Перед подтверждением проверяются подпись, номер, сумма и состояние платежа. Допускаются суммы с шестью десятичными знаками. Подтверждение сохраняет `paidAt` и не перезаписывает его при повторном уведомлении. Отметка оплаты загружается и в проекте, и в списке встреч ребёнка.

HTTP-тест `src/project-workflow.test.ts` проходит цепочку идея → проект → встреча → одобрение → запись → платёж → подписанное уведомление → отображение оплаты. Контроллеры и сервисы настоящие; авторизация и репозитории заменены изолированными фикстурами. Реальные списания и обращения к платёжному провайдеру не выполняются. Отдельные тесты проверяют запись подтверждения и SSR-гидратацию отложенной страницы.

## Панель и профиль преподавателя, список центров

Панель преподавателя загружает предстоящие встречи один раз и использует этот же список для счётчика. Подпись изменена на «Предстоящих встреч»: фильтра по текущей неделе нет. Ученики проектов загружаются пакетно и учитываются один раз по ID. Фиксированная сумма `35600` удалена; `debit` возвращает `null`, карточка дохода скрыта до определения правил расчёта.

Публичный профиль преподавателя загружает участников, центры проектов, встречи и авторов идей пакетами. Связанные данные сопоставляются по ID, независимо от порядка ответа. Отсутствующий автор идеи представлен как `null`. Список центров получает встречи одним запросом и группирует их по `placeId`; прежние правила включения прошлых и удалённых встреч сохранены.

Тесты проверяют постоянное число обращений к репозиториям для 1 и 50 проектов или центров, сопоставление по ID, уникальный подсчёт учеников и пустые списки. Схема БД и исторические платежи не меняются.
