# Демонстрационные мастерские Quantum

Для подключения из окружения агента используйте [порядок работы с MySQL](mysql-access.md): способы запуска, диагностика и проверка состояния после разрыва соединения.

Набор `quantum-workshops-v1` дополняет текущую базу: 12 новых идей, 18 проектов, 6 преподавателей, 4 центра Москвы, 12 семей, 24 ученика, 4 администратора и 40 опубликованных встреч. Профили, цены и центры вымышленные. Координаты обозначают условные точки в районах Москвы, а не реальные заведения. Фотографии сгенерированы и размещены в S3.

Четыре проекта по `toy-001`…`toy-004` являются исследованиями образцов. Исходный каталог, его неизвестные параметры, предположения и фотографии не обновляются. Платежи, сообщения, OAuth-вход и реальные контакты демонабор не создаёт.

## Запуск

Подключение берётся из `.env`. Сначала применить служебную миграцию и посмотреть предварительный отчёт:

```sh
npm run db:migrate:demo
node export-db-schema.mjs
npm run db:seed:demo
```

Запись и проверка:

```sh
npm run db:seed:demo -- --apply
npm run db:seed:demo:verify
```

Изображения можно подготовить отдельно, без доступа к MySQL: `npm run db:upload:demo-images`. Используется существующий `FileService.uploadBuffer`; повторная загрузка проверяет постоянные S3-ключи и не создаёт дубли объектов.

Повторный импорт сохраняет ID из `demoSeedRecord`, обновляет содержимое и переносит встречи на ближайшие три недели. Учителя и центры не имеют пересечений в расписании, занятия укладываются в часы 09:00–20:00 по Москве. Часовой пояс соединения и SQL-сессии установлен явно. Запись выполняется одной транзакцией, параллельные операции демонабора ограничены именованной блокировкой. Новая неизвестная таблица со ссылочными полями блокирует запуск до проверки её связей.

## Удаление

```sh
npm run db:seed:demo:remove
npm run db:seed:demo:remove -- --apply
```

Удаляются только записи, зарегистрированные в наборе. Внешние записи, связанные с демоданными (включая новые записи на занятия, платежи и чаты), блокируют удаление и повторное обновление. Таблица реестра и изображения S3 остаются для будущего повторного наполнения. Если запись из реестра отсутствует, операция завершается ошибкой вместо попытки переиспользовать случайный ID.

## Проверка

`npm test` проверяет содержание, даты, пересечения расписания и обнаружение внешних ссылок. `npm run check` проверяет также типы CLI-скриптов.

Главная и список проектов продолжают загружать данные при отказе или недоступности геолокации: в этом случае показывается общий список без координат.

`npm run test:demo:db` требует отдельного локального MySQL-совместимого сервера на `127.0.0.1:33079`. Настройки: `DEMO_TEST_DB_PORT`, `DEMO_TEST_DB_USER`, `DEMO_TEST_DB_PASSWORD`. Скрипт не загружает `.env`, создаёт базу со случайным новым именем и удаляет только её. Он проверяет откат частичного импорта, повторный запуск, постоянные ID, отсутствие пересечений, защиту удаления и сохранность исходного каталога. Для совместимости локальной MariaDB используется `utf8mb4_unicode_ci`; рабочая миграция сохраняет сопоставление MySQL `utf8mb4_0900_ai_ci`.

## Объединение, очистка и расширение

Служебные CLI по умолчанию печатают предварительный отчёт. Порядок применения:

Команды запускаются из корня репозитория. Новые CLI сначала компилируют поддерживаемые исходники из `scripts/` и `src/`, затем запускают JavaScript обычным Node. Сборка сохраняется в игнорируемой `.cache/demo/cli/`; это обход наблюдавшихся обрывов подключения MySQL при запуске через `tsx`. Исходники остаются в репозитории, а временные файлы можно пересоздать через `npm run build:demo-cli`.

```sh
npm run db:merge:demo-ideas
npm run db:merge:demo-ideas -- --apply
npm run db:cleanup:demo
npm run db:cleanup:demo -- --apply
npm run db:extend:demo
npm run db:extend:demo -- --apply
npm run db:extend:demo -- --verify
```

Объединение ищет парусник, робота и фонарь по `catalogId` наборов `quantum-passport-42-v1` и `quantum-workshops-v1`. Проекты сохраняют ID и переходят к общим идеям; лайки и фотографии переносятся без повторов, счётчики пересчитываются. Платежи за копии идеи перепривязываются к общей идее. Поддерживаемый `npm run db:seed:dmitry -- --apply` использует общие идеи и не восстанавливает копии. Он проверяет принадлежность аккаунта, ученика и центра перед записью.

Очистка физически удаляет идеи 33, 35, 13, 41, 12, 32, 50, 51, 46 и идеи с `NULL` или пробельным `image`; удаляет их проекты, другие проекты с пустой картинкой и все зависимые встречи, участников, лайки, фотографии, платежи и записи реестра. Пустое поле определяется по содержимому, без проверки доступности URL. Паспорта, ученики, центры, чаты и S3-объекты сохраняются.

Перед записью CLI проверяет реальные столбцы, внешние ключи, InnoDB и отсутствие непроверенных триггеров. Резервные выгрузки находятся в игнорируемой `.cache/demo/cleanup/<отпечаток-базы>/`. Первый предварительный запуск фиксирует `targets.json` с отпечатками строк. Повторный запуск использует тот же список: отсутствующие строки пропускаются, изменённые строки или переиспользованные ID блокируют удаление. Новые проекты, ссылающиеся на выбранную идею, также требуют проверки. Для новой отдельной очистки сначала сохраните старый каталог резервных копий и вручную проверьте новый список целей; автоматически список не расширяется.

Расширение добавляет 10 идей, 15 проектов, 33 встречи, 20 учеников и 10 вымышленных семей. Темы: змей, калейдоскоп, мост, планетарий, теплица, бумажный аквариум, кормушка, мозаика, магнитная рыбалка и настольная игра. Первые пять идей получают две реализации. Используются существующие демонстрационные преподаватели и центры; Дмитрию проекты не добавляются. В проекте 4–8 участников, на встрече 3–4. Встречи выбираются в ближайшие шесть московских недель с учётом часов центра и всех существующих занятий преподавателей, центров и участников.

Новые записи зарегистрированы с префиксом ключа `extension/` в `quantum-workshops-v1`. Повторное расширение проверяет существующие записи и сохраняет ID без обновлений. Неполный набор блокирует импорт. После расширения обновление расписания исходного демонабора блокируется до проверки, чтобы не создать пересечения. Защита удаления от внешних записей сохраняется для всего набора.

Изображения расширения можно загрузить отдельно: `npm run db:upload:demo-images -- --extension`. Десять отдельных сгенерированных JPEG находятся в [assets/demo-workshops/extension](../assets/demo-workshops/extension/); публичные ссылки после загрузки сохраняются в `extension/images.json`. Загрузка использует `FileService.uploadBuffer` и постоянные ключи с хешем содержимого. Ошибки сети не вызывают повторов записи в MySQL. Если соединение оборвалось во время применения, сначала выполните предварительный отчёт или `--verify`, чтобы установить состояние операции.

Изолированная проверка дополнительно покрывает физическое удаление всех зависимостей и откат, сохранение посторонних строк, защиту от переиспользованного ID, три объединения с переносом фотографий и платежей, повторное наполнение Дмитрия без копий и повторный импорт расширения. Тесты frontend проверяют возврат фильтров через историю, перезагрузку и серверный рендеринг.
