# Работа с MySQL из окружения агента

Проверено по истории запусков 10–11 октября 2026 года, исходникам и новой попытке подключения 11 октября. Это порядок работы для следующих сессий, а не гарантия доступности сервера.

## Что действительно сработало

- Обычный Node с `mysql2/promise`, настройками из `.env` и скомпилированным JavaScript. Поддерживаемые CLI собираются командой `npm.cmd run build:demo-cli`; результат находится в игнорируемой `.cache/demo/cli/`.
- Общий помощник [scripts/demo-cli.ts](../scripts/demo-cli.ts) использует `connectionLimit: 1`, `connectTimeout: 120000`, `timezone: '+03:00'` и явный TCP-поток через `node:net.createConnection`. После авторизации он устанавливает часовой пояс SQL-сессии, получает `GET_LOCK('quantum:demo-seed', 10)` и задаёт уровень изоляции.
- 11 октября в 08:59–09:00 UTC команда `node .cache/demo/cli/scripts/setup-wschool.js --apply` завершилась с кодом 0. Отчёт подтвердил `committed: true`, `placeId: 597`, `projectId: 160` и отсутствие оставшихся добавлений после повторного чтения. Резервная выгрузка сохранилась в `.cache/demo/cleanup/wschool-2026-10-11T08-59-56-060Z/`.
- Прямое подключение обычным Node без собственного `stream` тоже ранее работало. Сбой служебного CLI сам по себе не доказывает недоступность всех способов подключения.

В истории есть успешные и неуспешные запуски через `tsx`. Компиляция с последующим запуском обычным Node — уже принятый в проекте способ уменьшить зависимость от загрузчика; причинная связь между `tsx` и сетевыми сбоями не доказана. Не возвращаться к `npx tsx` как к первому способу диагностики.

## Порядок следующей попытки

Все команды запускать из корня репозитория. В Windows использовать `npm.cmd`.

1. Прочитать модели, репозитории и [database-schema.md](../database-schema.md). Проверить настройки через загрузку `.env`, не печатая его содержимое. Унаследованные переменные окружения могут иметь приоритет над `.env`; при подозрении сравнивать только булевы признаки совпадения.
2. Проверить транспорт командой `node diagnose-db.mjs`. Она сообщает DNS, TCP и наличие приветствия MySQL без вывода адреса и пароля. Открытый порт ещё не означает успешную авторизацию.
3. Если команда внутри песочницы получила `EACCES`/`EPERM`, повторить её через штатный запрос `sandbox_permissions: "require_escalated"`. Не пытаться обходить ограничение другим инструментом. Ошибки записи npm в пользовательский кеш также относятся к окружению, а не к данным MySQL.
4. Собрать CLI отдельно, затем выполнить предварительное чтение обычным Node. Так сетевой сбой не запускает сборку заново и не смешивается с её выводом:

   ```powershell
   npm.cmd run build:demo-cli
   node .cache/demo/cli/scripts/setup-wschool-rooms.js
   ```

   Эта команда без `--apply` проверяет состояние кабинетов центра №597 и откатывает транзакцию. Для проверки только подключения использовать `SELECT 1` через `mysql2/promise` с теми же настройками; не запускать импорт ради проверки связи.

5. Если чтение не удалось, допустима отдельная попытка прямого подключения обычным Node без собственного `stream`. Не менять `.env`, реквизиты, TLS, VPN или настройки безопасности на основании одного таймаута. Длинное ожидание до 120 секунд было частью успешных запусков, но не гарантирует результат. Для короткой диагностики задавать отдельный таймаут 10–15 секунд.
6. Применять изменения только после получения и проверки предварительного отчёта в рамках задачи пользователя. Для кабинетов предусмотрена команда:

   ```powershell
   node .cache/demo/cli/scripts/setup-wschool-rooms.js --apply
   ```

   Скрипт сохраняет резервную выгрузку, добавляет только отсутствующие кабинеты, выполняет одну транзакцию и читает результат после `COMMIT`. Подробности — в [wschool-setup.md](wschool-setup.md).

7. После разрыва связи при записи сначала прочитать фактическое состояние. Не повторять `--apply` вслепую: сервер мог завершить `COMMIT` до потери ответа. Успех подтверждать отчётом после фиксации и чтением сохранённых строк, а отображение — отдельно через API и страницу.

Сетевые попытки выполнять последовательно. Не держать несколько зависших импортов одновременно; при длительном запуске сохранять ID процесса/сессии, получать результат через `write_stdin` и сообщать пользователю состояние. После нескольких одинаковых сбоев сменить диагностическую проверку или сообщить конкретный блокер, а не многократно повторять запись.

## Как читать ошибки

| Наблюдение | Что установлено | Следующий шаг |
| --- | --- | --- |
| `EACCES`/`EPERM` в песочнице | Операция ограничена окружением; это не доказательство отказа сервера | Штатный разрешённый запуск вне песочницы |
| TCP открыт, приветствия нет | TCP установлено, протокол MySQL ещё не начался | Проверка авторизации через Node с ограниченным ожиданием; не менять SQL |
| `ETIMEDOUT` | Не завершилось подключение/рукопожатие за заданное время | Отдельная попытка чтения другим вариантом подключения |
| `ER_NET_READ_INTERRUPTED`, `PROTOCOL_CONNECTION_LOST`, пакеты вне порядка | Соединение прервано или протокол нарушен; состояние записи может быть неизвестно | Сначала чтение состояния; без автоматического повтора записи |
| `SELECT 1` успешен | Подключение и авторизация работают | Проверить нужные таблицы; затем операцию и её результат |

Последние сбои не устанавливают первопричину: возможны проблемы сервера или сетевого пути. Нельзя утверждать, что обязательно нужен VPN, что неверен пароль или что виноват `mysql2`, без отдельного подтверждения.

## Штатный клиент и тестовая база

В локальном кеше был найден `.cache/demo/server/mariadb-11.8.6-winx64/bin/mysql.exe`. Его пробовали как альтернативный клиент, но просмотренный отчёт проверки завершился `Native MySQL verification unavailable, exit 1`. Не считать этот вариант подтверждённым решением. Кеш не входит в Git, поэтому наличие исполняемого файла нужно проверять заново.

Если потребуется независимая проверка штатным клиентом, запускать его через `spawn` с массивом аргументов и `windowsHide: true`, без `shell: true`. Не передавать пароль в командной строке или выводе. В старом временном скрипте были `MYSQL_PWD` и `--ssl=FALSE`; это описание истории, не инструкция отключать TLS.

Изолированная MariaDB на `127.0.0.1:33079` использовалась для тестов транзакций, отката и повторного импорта. Успешный локальный тест не доказывает доступность рабочей базы из `.env` и не добавляет туда кабинеты. Подробности — в [demo-seed.md](demo-seed.md).
