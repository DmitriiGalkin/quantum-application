## Повторный запуск и восстановление

CLI: [scripts/update-center-content.ts](../scripts/update-center-content.ts).

```powershell
npm.cmd run build:demo-cli
node .cache/demo/cli/scripts/update-center-content.js --upload-covers
node .cache/demo/cli/scripts/update-center-content.js
node .cache/demo/cli/scripts/update-center-content.js --apply
```

Без флагов CLI выполняет предварительное чтение и откатывает транзакцию. Флаг загрузки требует локальные PNG в `.cache/center-updates/`. Режим применения требует подготовленный `covers.json`, проверяет фактические столбцы MySQL и доступность S3. Постоянные маркеры комментариев защищают от повторного создания заявок. Существующие заявки и их последующие изменения статуса не перезаписываются.

Резервная копия этой операции: `.cache/center-updates/backups/2026-10-14T13-53-12.128Z/before.json`; результат: `after.json` в той же папке. В копии сохранены полные строки затронутых центров, залов, заявок, проектов, встреч и идеи; реквизитов подключения нет. Автоматического повтора записи после сетевого сбоя нет: сначала нужно прочитать состояние.

Для адресного восстановления использовать прежние значения из `before.json` после проверки текущего состояния: вернуть обложки, флаги аренды, описание и значения `deletedAt`; удалять только демонстрационные заявки с указанными маркерами, если после операции ими ещё не пользовались. Не заменять таблицы целиком.
