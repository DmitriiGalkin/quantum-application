# Каталог идей

Изделие каталога — Idea. Project — отдельная реализация этой идеи мастером с детьми. Связь `project.ideaId` использует числовой `idea.id`. ID из JSON (`toy-001`) сохраняется в уникальном `idea.catalogId`, ID фотографий — в `ideaPhoto.id` с регистрозависимым сравнением.

## Миграция и импорт

```sh
npm run db:migrate:ideas
npm run db:import:ideas -- toy-catalog.json --dry-run
npm run db:import:ideas -- toy-catalog.json
node export-db-schema.mjs
```

Миграция проверяет наличие добавленных полей и таблицы; повторный запуск допустим. DDL MySQL не транзакционен, импорт выполняется отдельно в одной транзакции. Подключение берётся из `.env`, включая `DB_PORT`. CLI предназначен для оператора с доступом к БД; `passportId = NULL` обозначает общую импортированную идею без вымышленного владельца.

Повторный импорт обновляет идеи по постоянному ID, сохраняя числовой ID и связи с проектами. Состав и порядок фотографий импортируемых карточек заменяются атомарно. Идеи, отсутствующие в новом файле, не удаляются. Значения из файла заменяют ручные изменения этих карточек. Удалённые идеи не восстанавливаются автоматически: конфликт ID откатывает импорт. Коллизия ID фотографии с другой идеей также откатывает импорт.

Все исходные поля изделия, кроме `photos`, хранятся в JSON `idea.cardData`; фотографии целиком — в `ideaPhoto.photoData`. Метаданные верхнего уровня каталога, кроме `items`, сохраняются в `idea.catalogMetadata`. Неизвестные поля, `null`, пустые массивы, отсутствие поля и пометки об источниках/предположениях не преобразуются. Название, описание и URL обложки также записываются в прежние `title`, `description`, `image`.

Файлы изображений не скачиваются: ссылки Google Drive сохраняются вместе с `driveFileId`, именем файла и признаком обложки. Доступность изображений зависит от прав в Google Drive.

Импортер после записи сравнивает карточки из БД с исходным JSON, затем выполняет повторный импорт и проверяет сохранение числовых ID. Эта проверка требует доступного соединения с MySQL; таймаут после первой записи не отменяет уже завершённую транзакцию.

## API

| Метод | Путь | Действие |
| --- | --- | --- |
| GET | `/idea-cards` | Все активные карточки каталога |
| GET | `/idea-cards/:id` | Карточка по постоянному строковому ID |
| POST | `/idea-cards` | Создать карточку |
| PUT | `/idea-cards/:id` | Полностью заменить карточку, ID неизменяем |
| POST | `/idea-cards/import` | Импортировать каталог `schemaVersion: 1` |

POST/PUT требуют `Authorization: Bearer ...`; без токена — 401. Карточки с владельцем обновляет только этот Passport; общие карточки доступны авторизованным пользователям. HTTP-импорт назначает владельца новым карточкам, сохраняет владельца существующих и проверяет права каждой записи. Заголовок `X-Role` не даёт дополнительных прав.

Тело создания/обновления соответствует элементу `items` из [toy-catalog.json](../toy-catalog.json), включая `id`, `name`, `description`, `photos`. Ответ добавляет числовой `ideaId` для создания Project; перед PUT это служебное поле нужно исключить. Тело импорта — весь каталог. Ответ импорта: `{ "ideas": 4, "photos": 11 }`. Ошибки: 400 — неверные данные, 403 — чужая карточка, 404 — нет карточки, 409 — конфликт ID. POST возвращает 201, остальные операции — 200.

Сохраняются прежние `/ideas`, `/idea/:id` и POST `/idea`. Карточки каталога видны в прежних чтениях с `catalogId` и `cardData`; полный массив фотографий доступен через `/idea-cards`.
