# Каталог идей

Изделие каталога — Idea. Project — отдельная реализация этой идеи мастером с детьми. Связь `project.ideaId` использует числовой `idea.id`. ID из JSON (`toy-001`) сохраняется в уникальном `idea.catalogId`, ID фотографий — в `ideaPhoto.id` с регистрозависимым сравнением.

## Миграция и импорт

```sh
npm run db:migrate:ideas
npm run db:import:ideas -- toy-catalog.json --dry-run
npm run db:import:ideas -- toy-catalog.json
node export-db-schema.mjs
```

Миграция проверяет наличие добавленных полей и таблицы; повторный запуск допустим. DDL MySQL не транзакционен, импорт выполняется отдельно в одной транзакции. Подключение берётся из `.env`, включая `DB_PORT`. CLI предназначен для оператора с доступом к БД; `passportId = NULL` обозначает общую импортированную идею без вымышленного владельца.

Повторный импорт обновляет идеи по постоянному ID, сохраняя числовой ID и связи с проектами. Состав и порядок фотографий импортируемых карточек заменяются атомарно. Идеи, отсутствующие в новом файле, не удаляются. Значения из файла заменяют ручные изменения этих карточек. Удалённые идеи не восстанавливаются автоматически: конфликт ID откатывает импорт. Коллизия ID фотографии с другой идеей также откатывает импорт.

Все исходные поля изделия, кроме `photos`, хранятся в JSON `idea.cardData`; фотографии целиком — в `ideaPhoto.photoData`. Метаданные верхнего уровня каталога, кроме `items`, сохраняются в `idea.catalogMetadata`. Неизвестные поля, `null`, пустые массивы, отсутствие поля и пометки об источниках/предположениях не преобразуются. Название, описание и URL обложки также записываются в прежние `title`, `description`, `image`.

Для отображения на сайте оригиналы фотографий загружаются в S3 через `FileService.uploadBuffer` — тот же метод вызывает загрузка `/image`. В `photo.url` сохраняется публичный адрес изображения, в `photo.sourceUrl` — исходная ссылка Google Drive. `driveFileId`, постоянный ID, имя файла и признак обложки сохраняются. `idea.image` обновляется адресом обложки в S3.

Для переноса уже импортированных идей скачайте оригиналы из Drive в локальную папку под именами `<photo.id>.jpg`, затем выполните `npm run db:upload:idea-photos -- toy-catalog.json <папка>`. Это операторская команда с реквизитами из `.env`; она работает только с общими идеями каталога, не открывает новый HTTP-маршрут. После загрузки проверяются публичный доступ, MIME-тип и JPEG-содержимое каждого адреса. Повторный запуск пропускает загруженные фотографии. Повторный импорт исходного JSON сохраняет S3-ссылки для того же ID фотографии, `driveFileId` и исходного адреса.

Импортер после записи сравнивает карточки из БД с исходным JSON, затем выполняет повторный импорт и проверяет сохранение числовых ID. Эта проверка требует доступного соединения с MySQL; таймаут после первой записи не отменяет уже завершённую транзакцию.

## API

| Метод | Путь | Действие |
| --- | --- | --- |
| GET | `/ideas` | Все активные идеи, включая каталог и фотографии |
| GET | `/idea/:id` | Идея по числовому ID или постоянному ID каталога |
| POST | `/idea` | Создать идею; ответ — её числовой ID |
| PUT | `/idea/:id` | Обновить идею; постоянный ID неизменяем |
| POST | `/ideas/import` | Импортировать каталог `schemaVersion: 1` |

POST/PUT требуют `Authorization: Bearer ...`; без токена — 401. Карточки с владельцем обновляет только этот Passport; общие карточки доступны авторизованным пользователям. HTTP-импорт назначает владельца новым карточкам, сохраняет владельца существующих и проверяет права каждой записи. Заголовок `X-Role` не даёт дополнительных прав.

Тело создания/обновления использует существующие `title`, `description`; дополнительно принимает `catalogId`, `cardData` и `photos`. В `cardData` сохраняются исходные поля изделия, включая неизвестные значения и предположения. Системные поля не принимаются на запись. Если при обновлении `photos` или `cardData` не переданы, прежние значения сохраняются; пустой массив фотографий очищает фотографии. Название и описание синхронизируются с соответствующими полями исходных данных. `id` в ответе остаётся числовым и используется при создании Project. Тело импорта — весь [toy-catalog.json](../toy-catalog.json). Ответ импорта: `{ "ideas": 4, "photos": 11 }`. Ошибки: 400 — неверные данные, 403 — чужая идея, 404 — нет идеи, 409 — конфликт ID. POST создания возвращает 201, остальные операции — 200.

В коде используется одна сущность `Idea`, один `IdeaService`, один `IdeaRepository` и один контроллер идей. Отдельного представления `IdeaCard` и API `/idea-cards` нет. Тип `IdeaCatalog` описывает только формат файла импорта; он не является альтернативной сущностью идеи. Фотографии в API всегда находятся в `Idea.photos`.

Проверить сохранённый каталог без повторной записи: `npm run db:import:ideas -- toy-catalog.json --verify-only`.
