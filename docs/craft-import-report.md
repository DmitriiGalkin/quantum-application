## Источники и файлы

Все 25 исходных снимков учтены ровно один раз в [манифесте](craft-photo-manifest.json): 23 относятся к изделиям, два — к [школьной программе](craft-school-program.md). Для каждого оригинала сохранены имя, ID Drive, исходная ссылка, назначение, SHA-256 и публичный адрес Quantum. Программа расшифрована в порядке страниц, колонок, классов и разделов; рукописные пометки и сомнительное чтение отмечены отдельно.

Пять обложек созданы отдельными вызовами встроенного imagegen по фотографиям изделий и прежнему образцу стиля. Размер каждой — 1536×1024 (3:2). Изображения опубликованы в S3; точные промпты, идентификаторы результатов и входных референсов сохранены в `docs/image-prompts/catalog/`. Правила и исходные демонстрационные промпты — в [описании генерации](idea-image-generation.md). Обложки просмотрены и сопоставлены с исходными изделиями.

Оригиналы и обложки загружены через `FileService.uploadBuffer`. Для всех 30 файлов проверены публичный GET, MIME-тип и совпадение SHA-256 с локальным файлом. В БД галереи содержат адреса хранилища, оригиналы дополнительно сохраняют `sourceUrl` Google Drive. В `toy-catalog.json` URL оригиналов оставлены исходными ссылками Drive по принятому формату каталога; повторный импорт существующим сервисом сохраняет загруженные адреса по ID и происхождению фотографии. Адреса хранилища оригиналов также доступны в манифесте.

Резервная копия: `.cache/toy-photo-review/backups/2026-10-12T18-13-03-191Z/backup.json` (игнорируется Git). Импортируемый файл содержал только пять затронутых карточек.

После `COMMIT` прочитаны и полностью сопоставлены поля карточек и фотографии. Подтверждены `passportId = NULL`, постоянные и числовые ID, ровно одна обложка в каждой карточке и совпадение `idea.image` с её URL. Все 27 прежних идей и 12 прежних фотографий остались без изменений, включая их ID. Исходные четыре карточки в JSON сохранены целиком.

До успешной записи подключения были нестабильны. Первая попытка импорта завершилась таймаутом на получении соединения. Перед следующей попыткой заново прочитана БД: новые ID отсутствовали, прежние строки совпадали со снимком. Слепого повторения записи не было.

`npm.cmd run check` прошёл: ESLint, проверка типов, клиентская, SSR- и backend-сборки. Проверены JSON существующим валидатором, формат всех обложек, локальные ссылки Markdown, отсутствие повреждённой кодировки и полное соответствие манифеста 25 источникам.

## Страницы и предел проверки

Компонент `IdeaPage` успешно отрендерен на сервере для всех пяти карточек с полями и адресами фотографий, ранее полностью сопоставленными с БД. В полученном HTML проверены название, полное описание, пометка о генерации ИИ, порядок всех миниатюр (6, 8, 5, 6 и 3) и ровно одна выбранная обложка. HTML и отчёт сохранены локально в `.cache/toy-photo-review/pages/` и `render-result.json`. Гостевой контекст для этой отдельной проверки задан локально.

Полная проверка через HTTP API и визуальный просмотр в браузере остаются незавершёнными. Локальный неизменённый backend отвечал `200` на `/healthz`, но запрос карточки завершился таймаутом подключения к MySQL. Две отдельные попытки заранее установить соединение перед запуском API получили `PROTOCOL_CONNECTION_LOST`. В инвентаре инструмента компьютерного управления нет доступных браузеров или приложений. Это ограничение проверки не меняет подтверждённый результат `COMMIT` и последующего чтения всех импортированных карточек. Клиентская гидратация и взаимодействие с галереей в этой сессии не проверены.

Для последующего чтения без записи можно использовать существующий CLI с скомпилированным JavaScript:

```powershell
npm.cmd run build:demo-cli
node .cache/demo/cli/scripts/import-idea-catalog.js toy-catalog.json --verify-only
```

Для страницы идеи подходят оба вида ID: `/idea/83` и `/idea/toy-005` (аналогично для остальных строк таблицы). После потери соединения при любых следующих изменениях сначала читать сохранённое состояние, затем решать о записи.
