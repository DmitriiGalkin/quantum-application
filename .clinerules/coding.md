# Quantum

Quantum — образовательная платформа, объединяющая учеников, учителей и образовательные центры.

Этот документ описывает общие правила проекта. Любые изменения должны соответствовать данным правилам.

---

# Цель проекта

Создать единую образовательную платформу, где:

- ученик может находить занятия;
- учитель может создавать проекты и проводить встречи;
- образовательный центр предоставляет помещения и управляет своей деятельностью.

---

# Архитектура

Используется классическая трехслойная архитектура.

```
Controller
    ↓
Service
    ↓
Repository
    ↓
MySQL
```

---

# Ответственность слоев

## Controller

Отвечает только за HTTP.

Разрешено:

- чтение параметров запроса;
- получение body;
- проверка авторизации;
- возврат HTTP статусов.

Запрещено:

- SQL;
- бизнес-логика;
- работа с несколькими репозиториями.

---

## Service

Отвечает за бизнес-логику.

Сервис может:

- обращаться к нескольким Repository;
- выполнять проверки;
- реализовывать сценарии;
- создавать транзакции.

---

## Repository

Repository отвечает исключительно за работу с одной таблицей базы данных.

Repository:

- не знает о HTTP;
- работает только с SQL
- не знает о других Repository;
- не содержит бизнес-логики.

---

## SQL

Предпочитать понятные запросы.

Избегать сложной генерации SQL.

Использовать параметры вместо конкатенации строк.

---

# Общие принципы

Предпочитать простые решения.

Не использовать сложные паттерны без необходимости.

Не использовать ORM.

Работа с БД осуществляется через SQL.

Предпочитать читаемый код.

---

# DTO

DTO используются между frontend и backend.

Repository никогда не принимает DTO из API.

Service преобразует DTO в модели базы данных.

Repository работает только с моделями базы данных.

---

# TypeScript

Не использовать any.

Использовать строгую типизацию.

Использовать интерфейсы вместо object.

Использовать enum только если они действительно упрощают код.

---

# React

Компоненты должны быть максимально "глупыми".

Предпочитать Controlled Components.

Форма получает:

- values
- onChange
- onSubmit

Компонент формы не хранит собственное состояние данных.

---

# Backend

Любая бизнес-операция начинается в Service.

Даже если сейчас операция простая, она должна проходить через Service.

---

# SQL

Предпочитать явный SQL.

Запрос должен быть понятен без дополнительной логики.

Избегать чрезмерной генерации SQL.

---

# Производительность

Не оптимизировать преждевременно.

Сначала простой понятный код.

Оптимизация только после появления необходимости.

---

# MUI v9 & Grid Component Rules
- Мы используем Material UI версии 9 (MUI v9).
- ПОЛНОСТЬЮ ИГНОРИРУЙ старый синтаксис Grid v1 (`import Grid from '@mui/material/Grid'`).
- ВСЕГДА используй только новый Grid v2. Импортируй его строго так: `import Grid from '@mui/material/Grid2';` или из актуальной директории v9.
- В MUI v9 свойства `xs`, `sm`, `md`, `lg`, `xl` заменены на свойство `size`.
  - НЕПРАВИЛЬНО: `<Grid xs={12} md={6}>`
  - ПРАВИЛЬНО: `<Grid size={{ xs: 12, md: 6 }}>`
- Для отступов используй свойство `spacing` (например, `spacing={2}`). Свойства `rowSpacing` и `columnSpacing` передавай только при необходимости разделения.
- Если ты не уверен в существовании пропса в MUI v9, прочитай файл `package.json`

# MUI Component Styling Rules (Stack, Typography, etc.)
- ЗАПРЕЩЕНО использовать прямые стилевые пропсы (shortcut props) вроде `alignItems`, `justifyContent`, `flexDirection`, `gap`, `textAlign` непосредственно на компонентах MUI (включая <Stack>, <Typography>, <Box>).
- ВСЕ стилевые и флексбокс-свойства необходимо строго выносить внутрь объекта `sx`.
  - НЕПРАВИЛЬНО: `<Stack alignItems="center" justifyContent="space-between">`
  - НЕПРАВИЛЬНО: `<Typography textAlign="center">`
  - ПРАВИЛЬНО: `<Stack sx={{ alignItems: 'center', justifyContent: 'space-between' }}>`
  - ПРАВИЛЬНО: `<Typography sx={{ textAlign: 'center' }}>`
- Исключение: пропсы, которые являются частью семантического API компонента (например, `spacing` для <Stack>, `variant` и `component` для <Typography>, `size` для <Grid>).
- Перед тем как отдать готовый код, выполни self-check: убедись, что CSS-свойства
